# Specification: Z-Axis State Extension

**Track ID:** z-axis-states_20260228
**Type:** Feature
**Created:** 2026-02-28
**Status:** Draft

## Summary

Extend the state representation of the ball-balancing simulation to include a vertical (Z) translatory degree of freedom for both the ball and the table, expose manual state sliders in the ImGui GUI, update the 3D renderer to reflect all six states, add axis labels to the 3D view, and include the new states in the real-time plotter.

## Context

The product is an educational control-systems simulator. Currently the system models a 2D horizontal ball position with 2D table tilt angles. To support richer 3D dynamics and future controller/observer extensions, the state space must be extended to capture vertical motion of both the table platform and the ball. This track focuses purely on the representation and visualization layer — physics, control, and estimation are left unchanged and will be updated in a later track.

## User Story

As a control systems researcher, I want to explore 3D state dynamics so that I can study and visually verify full-state ball-table interaction, including vertical motion, before developing control laws for the extended system.

## Problem Description

Currently:
- `StateVector` is 6D: `[x, y, vx, vy, theta_x, theta_y]`
- The table has only two rotational states (roll/pitch) and no translatory Z
- The ball has no vertical position
- The renderer has no axis labels
- The plotter does not display all physically meaningful states

Desired:
- `StateVector` extended to 8D: `[x, y, z_ball, vx, vy, vz_ball, theta_x, theta_y]` for the ball, plus `z_table` as table state (total 9D or structured clearly)
- GUI sliders to set each state manually when the simulation is paused
- Renderer shows ball and table correctly positioned/oriented in 3D for all states
- Axis labels "X", "Y", "Z" visible in the 3D viewport
- Plotter includes all new states

## Acceptance Criteria

- [ ] `StateVector` extended to include `z_ball`, `vz_ball`, and `z_table` (or equivalent structured representation); index constants updated
- [ ] Ball has translatory states `[x, y, z_ball]` and velocities `[vx, vy, vz_ball]`
- [ ] Table has states `[varphi (roll/theta_x), theta (pitch/theta_y), z_table]`
- [ ] ImGui control panel has 6 manual-state sliders (x, y, z\_ball, theta\_x, theta\_y, z\_table) — visible and active **only when the simulation is paused**
- [ ] 3D renderer correctly translates the table by `z_table` along Z and the ball by its `[x, y, z_ball]` position
- [ ] Table rotation in renderer uses both `theta_x` (roll) and `theta_y` (pitch) from the state (already correct, no regression)
- [ ] Axis labels "X", "Y", "Z" are rendered at the tips of the coordinate axes in the 3D viewport
- [ ] `RealTimePlotter` / `DataManager` plots all extended states (z\_ball, vz\_ball, z\_table at minimum)

- Web/Emscripten build validation (desktop build only for this track)

## Technical Notes

- Extend `StateVector` from 6D to 9D (or similar) by adding `z_ball`, `vz_ball`, `z_table` entries and corresponding index constants in `state_index` namespace
- The physics `Simulator::step()` will set the new z-state derivatives to zero (no dynamics), so the vector grows without breaking existing logic
- ImGui sliders range suggestions: z\_ball ∈ [-0.1, 0.5] m, z\_table ∈ [-0.1, 0.2] m (adjust to taste)
- Axis labels can be implemented as 3D billboards or simple text rendered via ImGui overlay at projected screen positions
- `DataManager` struct fields must be extended; ring buffer capacity unchanged
