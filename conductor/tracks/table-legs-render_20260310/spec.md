# Specification: Table Legs Rendering & Kinematics Integration

**Track ID:** table-legs-render_20260310
**Type:** Feature
**Created:** 2026-03-10
**Status:** Draft

## Summary

Render the three physical arms of the parallel-mechanism table in 3D using line segments (lower link G→E and upper link E→T per arm), driven live by `TableKinematics` IK/FK, and expose arm parameters, servo angles, IK/FK mode, and servo dynamics via the GUI control panel.

## Context

The ball balancer uses a 3-DOF parallel-arm table. The kinematics code (`TableKinematics`) and all geometry math already exist in `src/physics/table_kinematics.cpp` / `include/ball_balancer/physics/table_kinematics.hpp`. The physics simulation currently commands tilt (φ, θ) and height (z_t) directly via `StateVector`; servo angles are implicit. This track makes the legs visible, adds a first-order servo dynamics model for each arm, hooks both IK and FK paths into the simulation, and provides GUI sliders to explore both control modes.

## User Story

As a developer experimenting with the ball balancer, I want to see the three physical arms rendered in the 3D viewport and be able to drive the table either by setting pose (IK → servo angles) or by moving individual servo angles (FK → table pose and ball follows), so that I can validate the kinematics model and design a later servo controller.

## Acceptance Criteria

- [ ] Three arms rendered in the 3D viewport: two line segments per arm (G→E lower link, E→T upper link), each arm a distinct colour, updated every frame from the current system state.
- [ ] Current servo angles α_i for all three arms are displayed in the GUI.
- [ ] FK verification display: computed (φ, θ, z_t) from servo angles shown alongside the actual state.
- [ ] GUI section "Arm Mechanism" exposes: L1, L2, Rg, Rt, z_nominal sliders; a show/hide toggle; IK failure indicator (red text when any arm is out of reach at the current pose).
- [ ] First-order servo dynamics: each arm angle evolves as dα/dt = (α_cmd − α) / τ_servo rather than snapping instantly, using the same `servo_time_constant` parameter already in `SystemParameters`.
- [ ] Two-mode GUI: **Pose mode** (set φ, θ, z_t → IK computes α_cmd) and **Servo mode** (set α_i directly → FK updates table pose and ball rides table).

## Technical Notes

- Leg rendering: reuse `grid_shader_` (pass-through colour shader), upload 12 vertices (2 per segment × 2 segments × 3 arms) to a dedicated `legs_mesh_` VAO each frame using `GL_DYNAMIC_DRAW`.
- Servo dynamics: integrate per-arm with Euler in the same 10-substep loop used for the ball (or a separate first-order update at control rate). State: `servo_angles_[3]`, targets updated by IK or GUI sliders.
- FK method: use `FKMethod::YouTubeClosedForm` for real-time servo mode (cheap, no iteration). Newton-Raphson available for display/debug.
- Coordinate mapping: arm geometry uses physics coordinates (X, Y horizontal; Z up). OpenGL maps: `GL_X = phys_X`, `GL_Y = phys_Z`, `GL_Z = phys_Y` — apply same transform as ball.
- The `TableKinematics` object is stateless; own the `ServoAngles` and `servo_cmd_angles_` in `Application` or a new `ArmState` struct.
